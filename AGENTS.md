# Agent Notes

## Localization (i18n)

Translations are an inlang project driven by `@inlang/paraglide-js`.

- **Message files:** edit `messages/{locale}.json`. Locales: `en` (base), `pt-br`, `zh`, `ja`, `ko`, `vi`, `id`.
- **Never edit `src/paraglide/`** — it is generated by `paraglide-js compile` (runs automatically via the vite plugin and the `build` script).
- **Usage in components:** `import { m } from '@/paraglide/messages.js'` then `m.message_key()` / `m.key({ placeholder })`. Locale resolution is automatic: `globalVariable` set by `src/middleware.ts` during prerender, `url` strategy on the client.
- **Routing:** Astro `i18n` config in `astro.config.mjs` mirrors `project.inlang/settings.json` locales — keep both in sync. Base locale (`en`) is unprefixed; other locales live under `/{locale}/` via `src/pages/[locale]/`. `urlPatterns` in the paraglide vite plugin must match this scheme.
- **Links:** use `localizeInternalHref(href)` from `src/lib/i18n.ts` for internal links (wraps paraglide's `localizeHref`, which must not be applied to external URLs).
- **Inline links inside messages:** use `{placeholder}` tokens and `linkify()` from `src/lib/i18n.ts` to re-attach anchors (see `MyStory.astro`).
- **Check translations:** `pnpm check:i18n` (uses `@inlang/cli`).
- Read `project.inlang/README.md` for the full inlang workflow (editors, machine translation).

## Agent awareness

- Session start / any work discussion: run `myco status --prompt`
  before proposing next steps — know the board first.
- User describes new work → offer to capture it (`myco todo add`,
  `issue new`, `proposal new`). Don't wait to be asked.
- Picking up a task: `myco resume <ID>` is the briefing.
- Wrapping up: `myco handoff <ID>` anything resumable; keep statuses
  honest (claimed → in-progress → blocked/done).
